OneLedger architecture decisions

ADR-0018 — Local owner sessions

Status: Accepted · Date: 2026-09-10 · Refines: ADR-0004, ADR-0014 and ADR-0016

Context

OneLedger will run on the owner’s laptop before it is deployed to a cloud server. Google OIDC is valuable at the public boundary, but it adds an external dependency and credential setup that local-only use does not need. Removing authorization entirely would expose every financial route and make local behavior unlike the deployed application.

Decision

The API has an explicit AUTH_MODE: local or google. Application code defaults to google. Local Compose configurations opt into local.

In local mode, GET /auth/login resolves exactly one configured owner, creates the same persisted twelve-hour app_session used by Google login, and sets the same signed, HttpOnly cookie. Every protected route still passes through require_owner; session expiry, revocation, household scoping and exact-origin mutation checks are unchanged.

Local mode is valid only when WEB_ORIGIN is an HTTP loopback origin. Any public or HTTPS origin fails at service startup. No session token is put in JavaScript, a URL or a checked-in file.

Google mode keeps authorization code flow, state, nonce, PKCE, signed identity verification, pinned-address checking and Google subject binding unchanged. A later cloud deployment selects it explicitly.

Alternatives considered

Bypass require_owner locally. Rejected: it removes the actual API boundary and leaves local mutations without the cookie-backed origin check.

Remove Google until deployment. Rejected: reintroducing authentication during deployment would create a second, late integration path. Keeping both modes under one login route makes the deployed path continuously testable.

Consequences

Local startup is offline and automatic after the owner row exists. The database still records and can revoke sessions, so tests and application behavior remain representative. The owner must set AUTH_MODE=google and configure Google OIDC before exposing OneLedger through a public origin; an unsafe copied local configuration refuses to boot.
