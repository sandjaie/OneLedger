ADR-0001 — Record architecture decisions

Status: Accepted · Date: 2026-09-04

Context

This project is specified in detail before any code is written, and will be built in evenings over an extended period by one person. The gap between deciding something and encountering the consequence may be months.

Without a record, two failure modes are near-certain: relitigating a settled question because the reasoning was forgotten, and — worse — quietly reversing a decision without noticing that something else depended on it.

Decision

Record every architecturally significant decision as an ADR: the context, the decision, the alternatives genuinely considered, and the trade-off accepted.

"Architecturally significant" means it would be expensive to reverse, or it constrains other decisions. Library choices are usually not. Data model conventions, currency handling and tenancy always are.

Consequences

Good. Reasoning survives. New decisions can be checked for conflict. A decision that turns out wrong can be reversed deliberately, with its dependants identified.

Cost. Writing an ADR takes time that could go into code. Accepted as cheap relative to the cost of rebuilding something because the reason for its shape was forgotten.

Rule. Accepted ADRs are not edited to reflect new thinking. A change is a new ADR that supersedes the old, which stays in place marked as superseded.
