ADR-0003 — Defer all AI to V2

Status: Accepted · Date: 2026-09-04

Context

AI is an obvious fit for two features here: classifying transactions that rules miss, and answering natural-language questions over the ledger.

It is also the easiest place to spend a lot of effort on something that turns out not to be the bottleneck. And it raises a privacy question — whether transaction data may be sent to a third-party API — that has not been decided and should not be decided implicitly by shipping a feature that depends on the answer.

Decision

No LLM calls in Phase 1 or Phase 2. Classification is a fully deterministic cascade. Ask My Finances is V2.

The classified_by enum reserves an ai value so no migration is needed later, but nothing writes it.

Rationale

The rules engine has to be good regardless. Personal spending is a few hundred recurring merchants. That is pattern matching, not language understanding. If the deterministic engine reaches 90%+ — which it should — then AI is handling a handful of rows per import, and its value is correspondingly small. Building AI first would mask a weak rule engine rather than complement a strong one.

Deterministic beats probabilistic for auditability. Every classification can name the rule that produced it. "The model thought so" is not an answer you can act on when a category looks wrong.

Ask My Finances is easier after Phase 1, not harder. It works by generating SQL against a normalized schema. That schema is the Phase 1 deliverable. Attempting it earlier would mean a model reading raw statements — expensive, slow and unreliable. Waiting makes it a smaller problem.

The privacy decision deserves to be made explicitly. Sending transaction data to a third-party API is a real choice with real trade-offs. It should be made deliberately, in its own ADR, with a specified redaction boundary — not arrived at because a feature happened to need it.

Prerequisites before V2 AI work starts

  1. The rule engine is measurably above 90% coverage.
  2. A privacy decision is recorded in its own ADR: what is sent, what is redacted, what the provider retains, and whether it is switchable per import.
  3. Cost per import is measured, not assumed.
  4. For Ask My Finances: a query safety layer — read-only role, statement timeout, row limits, and generated SQL shown to the user before execution.

Consequences

Good. Phase 1 and 2 have no external dependency, no per-use cost, no privacy exposure, and fully reproducible behaviour. Scope creep toward AI is blocked structurally rather than by willpower.

Cost. A handful of transactions per import land in the review queue that a model might have classified. That is a small, visible cost — and the review queue exists anyway.

This ADR is the scope-control mechanism. "Should we just add a quick AI fallback?" has a written answer: not until the four prerequisites hold.
