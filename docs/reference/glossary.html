13 — Glossary

Terms are used precisely and consistently across all specifications. Where a word has a loose everyday meaning and a specific meaning here, the specific one wins.

Core ledger

Account — Anything holding value or owing it. A bank account, a credit card, a loan, a brokerage account, a property, a gold holding. The universal model that avoids separate systems per institution or country.

Account class — asset or liability. Derived from account type; stored for query performance.

Amount — The signed monetary value of a transaction in the account's currency. Negative means money left the account. Immutable once written (Invariant I1).

Booked date — The date a transaction posted to the account. The date used for FX freezing and for all period reporting. Distinct from value date.

Frozen amount — amount_base and amount_secondary, computed once at import using the transaction-date rate and never recomputed (Invariant I5).

Ledger — The single transaction table containing every financial event across both countries. The centre of the system; nearly every feature is a query over it.

Reportable transaction — A transaction that counts as income or expense: not a transfer leg, not excluded, not an investment or loan flow. Defined by the v_transaction_reportable view.

Transaction type — What kind of event a row is: income, expense, transfer_in, investment_buy, loan_repayment and so on. Determines which reports include it.

Value date — The date the bank applies for interest calculation. Recorded where available; not used for reporting.

Currency and FX

Peg — A currency held at a fixed rate against another, recorded as currency.pegged_to and currency.peg_rate. Its rates are derived rather than fetched, and stored with source = 'derived_peg'. The UAE dirham is fixed at 3.6725 AED = 1 USD, which lets AED/INR be derived from USD/INR, so only one volatile rate needs tracking.

Base currency — household.base_currency: the currency headline figures are shown in, and what every *_base column holds. Secondary currency is household.secondary_currency, reached by the toggle. Which is shown is a display choice, not a data asymmetry — both are stored frozen per row. Which two currencies the pair contains is chosen at setup and changing it later is a backfill.

Carried-forward rate — The previous published rate, used on a weekend or holiday when no rate was published. Always flagged; never interpolated (Invariant I7).

Effective rate — What a transfer actually achieved: destination_amount ÷ source_amount. Compare against the market rate to find the spread.

FX spread cost — The gap between the market rate and the rate actually received on a transfer. Usually larger than the disclosed fee, and invisible on any bank statement.

FX translation gain/loss — The change in base-currency net worth caused purely by exchange rate movement. A genuine change in wealth, shown as its own line in attribution.

Implied rate — Synonym for effective rate.

Market rate / mid-market rate — The reference exchange rate for a date, from the ECB via the peg derivation. What a transfer should have been worth.

Pivot currency — A single intermediate currency all conversions route through. Considered and rejected in favour of frozen dual amounts (ADR-0003).

Import

Dedupe hash — SHA-256 of account, date, amount, normalized description and reference. Prevents the same transaction importing twice from overlapping statements.

Document checksum — SHA-256 of an uploaded file. Prevents importing the same file twice.

Golden fixture — A redacted sample statement with its expected parse output, asserted in tests. Breaks loudly when a bank changes layout.

Import batch — One statement's journey through the pipeline, from upload to commit. Carries row counts and the reconciliation result.

Near-duplicate — Same account, same amount, within ±3 days, description similarity ≥ 0.85. Warned, not blocked — it might be a genuine double charge.

Parser — Institution-specific code extracting rows from a statement. Versioned, because banks change layouts without notice.

Reconciliation — Verifying opening + Σ(rows) = declared closing. Blocks the import on mismatch (Invariant I8). The highest-value check in the pipeline.

Staged transaction — A parsed, normalized, classified row awaiting review. Becomes a transaction on commit.

Classification

Bucket — The coarse classification carried by every category: need, want, investment, debt_service, income, ignore. Gives the Needs/Wants/Investments/Debt view without a second classification pass.

Cascade — The ordered sequence of classification strategies. First match wins. Fully deterministic in Phase 1 and Phase 2.

Category — Two-level: category → subcategory. Ships with a curated seed taxonomy; the tree is universal, the merchant rules that fill it come from country rule packs.

Classification confidence — 0–1, determining whether a row is pre-ticked in review or surfaced for attention. Threshold 0.80.

Merchant alias — A pattern mapping a statement description to a canonical merchant. Many aliases per merchant, since the same shop appears differently across statements.

Rule — Matchers plus outcomes. All non-null matchers must match. User rules outrank seed rules by priority.

Seed rule — A rule shipping with the product, so reports work on the first import. Roughly 120 covering UAE, India and global merchants.

Transfers

External transfer — Money sent to an account not tracked in the system. Excluded from spending, but shown separately from internal movements.

Leg — One side of a transfer. A transfer has a source leg and a destination leg, each an ordinary transaction row carrying transfer_id.

Pending transfer — A leg whose peer hasn't been imported yet. Excluded from spending; re-matched automatically on later imports.

Remittance — A cross-border, cross-currency transfer. The case where FX cost tracking matters most.

Split transfer — One source leg matched to multiple destination legs, or vice versa.

Transfer — Money moving between two accounts you control. Never income, never expense (Invariant I3).

Investments

Asset class — The seven top-level buckets: Indian equity, international equity, debt, gold, cash, real estate, other. The primary portfolio view.

CAS — Consolidated Account Statement. A single statement covering all Indian mutual fund holdings across AMCs, from CAMS or KFintech.

Holding — A position: one security, in one account, for one owner. Units and value are materialized from investment transactions.

Investment transaction — A single lot: a purchase, SIP instalment, redemption, dividend or switch, with units and NAV. The level of detail that makes XIRR possible.

Lot — An individual acquisition with its own date, units and price. Required for accurate capital-gains basis.

NAV — Net Asset Value. The per-unit price of a mutual fund.

Security — An instrument: a fund, stock, ETF, bond, or gold product. Identified by ISIN, AMFI scheme code or ticker.

Valuation snapshot — A manual "as of date X this is worth Y" record for assets with no importable statement. Carried forward flat, never extrapolated.

XIRR — Extended Internal Rate of Return: the annualised return accounting for the timing of irregular cash flows. The correct return measure for SIPs, and impossible to reconstruct from snapshots.

Liabilities

Amortisation schedule — The full instalment-by-instalment breakdown of a loan into principal and interest. Regenerated as a new version on any rate change or prepayment.

EMI — Equated Monthly Instalment. The fixed monthly loan payment.

Loan event — A change to a loan's terms: prepayment, rate change, EMI revision, moratorium. Triggers schedule regeneration.

Prepayment — A payment beyond the scheduled EMI, reducing principal and shortening the loan.

Schedule version — Each regeneration increments the version; prior versions are retained, so "interest saved by prepaying" is computable rather than remembered.

Statement balance — What a credit card statement says is due, as of the statement date. Distinct from current outstanding, which includes transactions since.

Utilisation — Card outstanding ÷ credit limit. Computed, never stored.

Net worth

Attribution — The decomposition of a net-worth change into its causes: contributions, market appreciation, principal reduction, FX translation, revaluation, and the residual.

Liquid net worth — Net worth excluding property, locked retirement accounts and anything not convertible within roughly a month. Often the more actionable number.

Net worth — SUM(balance_in_base) across all accounts. One aggregate, because balances are signed (Invariant I2).

Net worth snapshot — A stored month-end computation, including the rates used, so the historical trend is reproducible.

Unexplained residual — The part of a net-worth change that attribution cannot account for. Displayed, never hidden — it is the best data-quality signal the system produces.

System

Audit log — Append-only record of every change to financial data. Insert-only at the database grant level.

Household — The tenancy boundary. One household in Phase 1; the column exists so a second person can be added without a schema migration.

Import path — The pipeline that parses statements: pdfplumber → words → parser → normalize → dedupe → FX freeze → reconcile → stage. It runs in the API service on a machine you control, so the file bytes reach no third party (ADR-0017). There is no separate importer and no CLI.

Invariant — One of the eight properties in prd.html §4 that must always hold. Each has a test; violating one produces silently wrong numbers.

Never-store list — The credentials and identifiers this system deliberately never holds. The strongest security control available (security-and-privacy.html).

RLS — Row Level Security. Postgres policies restricting rows by household. Enabled from day one even with one user.

Regional

AMFI — Association of Mutual Funds in India. Publishes the daily NAV file used for fund valuation.

DEWA — Dubai Electricity and Water Authority. Appears constantly in UAE statements.

EPF / PPF / NPS — Indian retirement vehicles: Employees' Provident Fund, Public Provident Fund, National Pension System. Typically valued by manual snapshot.

NRE account — Non-Resident External. Holds foreign earnings in INR; freely repatriable; interest tax-free in India.

NRO account — Non-Resident Ordinary. Holds India-sourced income; repatriation restricted; interest taxable.

Salik — Dubai's road toll system.

SIP — Systematic Investment Plan. A fixed recurring mutual fund investment. The dominant investment pattern in India and the main reason XIRR matters.

Tax residency context — Which jurisdiction's tax rules apply to an account. An attribute, not a separate module.
