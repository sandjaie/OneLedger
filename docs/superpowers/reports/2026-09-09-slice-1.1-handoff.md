### Two owner decisions were taken — both recorded in spec §8

**Decision 1 — `inverts_sign` reframes whatever stated no direction.** It is the statement's

`routes/layouts.py`: `inversion_matches_its_convention` and `DIRECTIONLESS_CONVENTIONS` are
**removed**. `has_a_balance_anchor` guarantees every saved layout declares an anchor, so no

### The card profile that works

```jsonc
{
  "name": "Card statement",                      // generic — never an institution name
  "fingerprints": ["Credit Card Statement", "Card Type:"],
  "columns": [
    { "field": "booked_date",  "xMin": 30,  "xMax": 120 },
    { "field": "value_date",   "xMin": 120, "xMax": 195 },
    { "field": "description",  "xMin": 195, "xMax": 460 },
    { "field": "amount",       "xMin": 460, "xMax": 580 }
  ],
  "dateFormat": "dd/MM/yyyy",
  "signConvention": "cr_suffix",
  "invertsSign": true,                           // legal as of this branch
  "chronologicalOrder": "ascending",
  "rowStartRule": "has_date_and_amount",
  "continuationRule": "no_date_and_no_amount",
  "quirks": ["filter_script:arabic"],
  "hasRunningBalance": false,
  "metadataPatterns": null                       // deliberately no period capture — see below
}
```

Header row is `Transaction Date | Posting Date | Description | Amount`, page 1 at `top=373.3`.
Measured result on the Aug-2026 file: **85 rows, 64 lines unparsed, 991 Arabic words filtered.**

### Four things that will bite

1. **The balance anchors are a two-line block on page 4**, not a labelled value. The labels are
   one physical line and the six figures the next:
   `Previous Statement Due | Purchase / Cash Advance | Interest / Other Charges | Payments /
   Credits | Total Payment Due | Current Balance` then `6,140.40 4,479.18 0.00 6,140.40
   4,479.18 13,728.34`. Opening is figure 1, **closing is figure 5 (Total Payment Due)** — not
   figure 6. `Current Balance` (13,728.34) is Total Payment Due plus the remaining installment
   principal and does **not** reconcile. `engine._capture` uses `IGNORECASE | MULTILINE` and
   **not** `DOTALL`, so `.` stops at the newline — anchor on the label line, then `\n`, then
   count figures.

2. **The period must be DERIVED, never captured.** The statement's installment block prints
   each plan's *original purchase date* (`09/04/2026`, `02/09/2025`) while the period is
   `26-Jul-26 to 25-Aug-26`. Those instalment charges are legitimately part of the declared
   purchase total the anchors reconcile against, so capturing the period would fail those rows
   and break the identity. `dateFormat` carries a four-digit year, so deriving is permitted.
   (Separately: the printed period uses a two-digit year, which `normalize._period_bounds`
   refuses anyway — it requires both bounds under one four-digit-year format.)

3. **`continuation:no_date_and_no_amount` runs past the end of the transaction table**,
   appending five pages of legal furniture to the last row's `description_raw`. Contain it with
   `skip_line_patterns` — data, not code. It moves no amount and no verdict. Note the
   installment lines are `<date> INSTALLMENT PLAN EMI …`, so a `^`-anchored pattern will not
   match; do not anchor.

4. **The amount word sits ~2pt below its own row** (`top=421.54` against `419.54`). Line
   grouping must tolerate that; `words.py` infers tolerance from modal character height
   (~9pt here), which is why it currently works. Do not hard-code a tighter tolerance.

### The arithmetic that proves the frame (Aug-2026 file)

```text
rows, ledger-signed, cr_suffix, no inversion   = +1,661.22
Previous Statement Due  6,140.40  (bare, owed)  → framed −6,140.40
Total Payment Due       4,479.18  (bare, owed)  → framed −4,479.18
−6,140.40 + 1,661.22 = −4,479.18                ✓ matched
```

Without the frame switch it computes `+7,801.62` against `+4,479.18` — the mismatch that
blocked all 38 files.

## 5. Process that binds every remaining branch

- Cycle: **plan → implement (TDD) → `/verify` → `/oneledger-code-review` (one round) → fix
  blocking → `/verify` → first push → PR → merge → delete branch.** Codex/external review is
  disabled — never wait for it.
- Nothing reaches `origin` unreviewed. `--no-verify` is not an option.
- Diff budget 800 / 1,600 soft, 1,200 / 2,400 hard; `ONELEDGER_SIZE_OVERRIDE="reason"` past the
  hard stop, with the same reason in the PR's Notes.
- `docs/superpowers/progress.md` is updated **on the task branch, in the head that gets
  merged**. No parallel trackers.
- Money: `Decimal` / `NUMERIC(20,4)` / string on the wire. No institution, currency or country
  name as an identifier. `require_owner()` is the boundary. Reports read
  `v_transaction_reportable`. Migrations forward-only via Flyway; never edit an applied one.
- Deviations from the plan go in the PR and `progress.md`, never by editing the plan after
  dispatch.
- UI branches: build to `docs/product/mockups/` (`OneLedger.dc.html`, `Review.dc.html`,
  `NetWorth.dc.html`, `LayoutMapping.dc.html`) — the owner's instruction is that these are
  exactly how the UI should look.
