# Seeds

Data a database needs that no migration writes. Applied by hand, once, against a database that
has already been migrated.

| File | What it is | How it is applied |
| --- | --- | --- |
| `institutions.sql` | The starter institution rows | `psql "$(scripts/dsn.sh)" -f db/seeds/institutions.sql` |
| `card-layout.json` | A `POST /layouts` body for the card statement layout | through the API, not `psql` — see below |
| `account-layout.json` | A `POST /layouts` body for the current-account statement layout | the same way |

## Neither profile carries an `institutionId`

Institution ids are generated by whichever database applied `institutions.sql`, so one committed
here fails its foreign key on another machine, or — worse — resolves to a different institution
that happens to hold that id.
`api/tests/test_seeded_layouts.py` validates every file in this directory through `LayoutCreate`
on every run and refuses one carrying an institution id, so a profile dropped in here needs no
test of its own.

## `card-layout.json`

A `statement_layout` row is household-scoped and is validated by `LayoutCreate`, so it is seeded
through `POST /layouts` rather than by an `INSERT`. A raw insert would bypass every rule that
model enforces — band ordering, sign-convention agreement, the quirks vocabulary, regex
compilation — and could store a profile the application refuses to save and cannot use. The
mapping UI supersedes this file entirely once it arrives; until then this is the same body that
UI would post.

`api/tests/test_seeded_layouts.py` holds every file in this directory to that: each is
validated through `LayoutCreate` on every test run, so a seeded profile cannot drift out of the
shape the endpoint accepts — and a layout added here is covered from the day it lands rather
than from the day someone writes it a test. It also refuses a profile carrying an
`institutionId`: `institutions.sql` inserts without ids, so every institution's key is whatever
`gen_random_uuid()` produced on the machine that applied it, and a key exported with a profile
either fails its foreign key elsewhere or, worse, resolves to a different institution. The
mapper UI sets it per household when it arrives.

Three of its values are not obvious, and each is measured rather than assumed.

**The balance anchors match a line of run-together figures, not a label.** The producer emits no
space characters between cells, so the statement summary extracts as one line of six figures
with no separator between them — `4,500.001,310.000.002,000.003,810.009,050.00` in the shape the
tests use. A regex anchored on the label cannot split them, which is the same reason
[statement ingestion](../../docs/design/statement-ingestion.html) calls word coordinates
mandatory for this producer. Each figure ends in exactly two decimal places, so
`\d[\d,]*\.\d{2}` segments the run deterministically; the patterns require exactly six figures on
their own line and capture the first and the fifth. The fifth is the total payment due. The sixth
is the current balance, which also carries any remaining installment principal and reconciles
against nothing.

**`continuationRule` is null.** With `no_date_and_no_amount` the last row absorbs every trailing
line of the document — 2,232 characters of page furniture in one `description_raw`. Off, the
longest description is 46 characters. The dropped lines are counted in `lines_unparsed` and
reported in the parse summary, so the loss is visible rather than silent (Invariant 7). This
card writes each transaction on one physical line; a layout whose narration genuinely wraps sets
the rule on.

**No statement period is captured.** The card's installment block prints each plan's original
purchase date, so the statement legitimately carries rows dated outside its own period — and
those instalment charges are part of the declared purchase total the anchors reconcile against.
Capturing the period would fail those rows and break the identity. `dateFormat` carries a
four-digit year, so the derived period is sound.

Measured across the card statements held locally: every one of them reconciles `matched`, with
no row failing to normalize. Those files are git-ignored and never enter this repository, and
no figure from any of them appears in this one — the example above and the fixtures in
`api/tests/test_ingest_card_frame.py` are invented, and reproduce the arithmetic rather than
the amounts.

## `account-layout.json`

A current account, and the second producer this repository has met. Its statements print a
running balance, wrap their narration over several physical lines, and are the first here to
state their own period. Five of its values are measured rather than assumed.

**It writes no space character between cells, so every pattern uses `\s*` and never `\s+`.**
The same producer trait the card layout meets, and the same trap, reached from the other side:
here the patterns match *labels* rather than figures, and a single `\s+` between two words that
sit in different cells captures nothing at all. The statement period extracts as
`PERIOD OF01 Mar 2026to31 Mar 2026` and the column header as `DateDescriptionDebitsCreditsBalance`
— run-together in the shape the tests use. Written with `\s+`, the period capture fails on every
statement measured and the whole file is refused; the fingerprints score zero and the layout is
never identified at all.

**Its rows run newest first.** Nothing on the page says so, and both orders parse every row.
Read ascending, the running-balance walk breaks on twenty of the twenty-one statements measured;
the twenty-first is a five-day month with one transaction, which closes whichever way it is read
— so a single statement is not enough evidence to set this field, and the one that would have
been checked first is exactly the one that proves nothing.

**One `amount` band spans both money columns.** The header names two — debits and credits — but
the document draws no boundary between them, and the figures themselves state their direction: a
debit carries a leading `-`, a credit carries no sign. Across the statements measured the debit
figures' midpoints cluster at x≈315 and the credits' between x≈370 and x≈400, with nothing in
between to place a split on. `debit_credit_columns` reconciles every statement too, with the
split guessed at x=345, and was rejected for that reason: it discards each figure's own sign in
favour of a boundary the producer never draws, so a wider debit printed further left would be
read as a credit and the walk would break on a file nobody has seen yet. Under `signed` the sign
is read from the figure, and the band only has to be wide enough to hold both columns.

**The skip patterns are load-bearing, and only because the continuation rule is on.** With
`no_date_and_no_amount` and no skip patterns, 43 of the 307 rows measured absorb the page
footer's legend into their narration, and the last row of every page but the last also absorbs
the next page's repeated column header. Neither corrupts a figure, so every statement still
reconciles `matched` — which is what makes this worth writing down rather than noticing later.
Two patterns remove both. The legend's second line needs none: it sits in the date band, so the
description column is empty and the line is dropped and counted. Note that the patterns are
matched against the space-joined line, not the run-together raw text, which is why these two
alone among the profile's patterns use `\s+`.

**Unlike the card, it captures its statement period.** A current account prints no installment
block, so no row is dated outside the period the statement declares, and the captured bounds gate
the row dates instead of being derived from them. Both bounds come from one line and one capture
each, as `LayoutCreate` requires.

`rowStartRule` is `has_date`. No line of the statements measured carries a date without an
amount, so `has_date_and_amount` reads all of them identically; the two differ only on a line
neither has met, where `has_date` makes a row that fails to normalize and blocks the batch while
`has_date_and_amount` drops it into `lines_unparsed` and lets the rest reconcile without it.
`api/tests/test_ingest_account_frame.py` pins that difference, since nothing in the statements
themselves would catch a change to it.

Measured across the current-account statements held locally: all twenty-one reconcile `matched`,
307 rows, none failing to normalize, every period stated rather than derived. Those files are
git-ignored and never enter this repository, and no figure from any of them appears in it — the
fixtures in `api/tests/test_ingest_account_frame.py` are invented and reproduce the arithmetic
rather than the amounts.
